Three blind detectors, one correlated story.

CLAIRE (Cross-Layer AI-driven Incident Response and Explanation) watches network, OS, and cloud activity with three independent anomaly detectors that never see each other's data, then fuses their alerts into a single attack narrative and has an LLM explain it in plain English. Every stage was deliberately attacked before being called done.

● THE PROBLEM

One tool sees a port scan. Another sees a privilege escalation. Neither sees the attack.

A real intrusion rarely stays in one place: a network scan, then a privileged process on a host, then a new IAM role in the cloud. Each event looks only mildly suspicious by itself. Correlated, they're an obvious multi-stage attack. Most security teams still do that correlation by hand, across separate network, endpoint, and cloud tools, which is one of the most-cited causes of alert fatigue and slow incident response in the industry today. CLAIRE automates the correlation, then explains what it found in plain English instead of just flagging it.

● ARCHITECTURE

No detector sees the whole picture. That's the point.

Each layer watches a completely different kind of data and never sees the others' features: real captured network traffic and endpoint syscalls, alongside a project-generated cloud dataset modeled on real CloudTrail logs. Fusion links their alerts only after the fact, by shared identity and time.

Why unsupervised, not supervised

A labeled classifier only recognizes the attack patterns it's already been shown. These detectors flag statistical rarity instead, so a genuinely new attack still gets caught without a labeled example of it existing in advance.

Why three detectors, not one model

Network, OS, and cloud data don't share a feature space: one is flow statistics, one is syscalls, one is API metadata. Merging them would blank out what makes each layer meaningful. Fusion correlates the three afterward instead, by identity and time.

CRITICAL
Step 1: Network layer (10:00 UTC). An unusually high-scoring network anomaly was flagged. The overall network behavior deviated strongly from baseline (abnormal traffic pattern / volume). Step 2: OS layer (10:04 UTC). Shortly after, the same host showed a similarly high-scoring OS anomaly, a broad deviation in OS activity the model deemed suspicious. Step 3: Cloud layer (10:08 UTC). Within minutes, a cloud-service anomaly was recorded for the same entity, a significant departure from normal cloud usage. Interpretation: the tightly-coupled network → OS → cloud sequence, all at anomaly score 0.95 within an 8-minute window, strongly points to a coordinated, multi-stage intrusion: initial foothold, local exploitation, then a pivot into the cloud environment. The cross-layer finding

All three detectors, tested on three different datasets, hit the same wall independently: naively retraining an unsupervised, density-based detector on adversarial examples doesn't reliably improve robustness. Adding examples only makes a region of feature space look more crowded, not more wrong.

Testing a second algorithm family (LocalOutlierFactor instead of IsolationForest) went further: some distance-based detectors can't even establish a usable baseline on purely categorical data. It's a question of which paradigm fits which data, not only which defense works.
