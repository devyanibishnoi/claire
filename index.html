Fusion: all three records share entity = host = "incident_demo_01", and every timestamp falls within 8 minutes of the first — well inside the 10-minute correlation window. Fusion links them into a single three-layer attack chain instead of three unrelated alerts.
CRITICAL
Step 1 – Network layer (10:00 UTC) – An unusually high-scoring network anomaly was flagged. The overall network behavior deviated strongly from baseline (abnormal traffic pattern / volume). Step 2 – OS layer (10:04 UTC) – Shortly after, the same host showed a similarly high-scoring OS anomaly — a broad deviation in OS activity the model deemed suspicious. Step 3 – Cloud layer (10:08 UTC) – Within minutes, a cloud-service anomaly was recorded for the same entity — a significant departure from normal cloud usage. Interpretation: the tightly-coupled network → OS → cloud sequence, all at anomaly score 0.95 within an 8-minute window, strongly points to a coordinated, multi-stage intrusion: initial foothold, local exploitation, then a pivot into the cloud environment. Severity Rating: Critical — high-confidence alerts across multiple layers with rapid progression warrant immediate investigation and containment.

The cross-layer finding
All three detectors — on three different datasets (synthetic cloud, real network flow, real OS syscalls) — independently hit the same wall: naively retraining an unsupervised, density-based detector with adversarial examples doesn’t reliably improve robustness, because adding examples only makes a region of feature space look more crowded, not more “wrong.” Repeating the experiment with a second algorithm family (LocalOutlierFactor instead of IsolationForest) surfaced a further, structural nuance: local, distance-based detectors can fail to even establish a usable baseline on purely categorical feature spaces, for reasons distinct from adversarial robustness entirely — a finding about which detection paradigm suits which data shape, not just about defenses.
